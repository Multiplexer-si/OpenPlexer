## Known limitations

- The hooks limit accidental agent overreach. A process running as the developer can bypass them or change their state. Private-area reads, a separate `git.push` check, unmatched tools, and writes the shell parser misses are outside hook coverage. There is no post-command check. A missing, killed, or timed-out Codex hook can let a call run. [Trust model](../trust-model.md#the-gate-stops-what-the-hooks-show-it-and-nothing-else)
- The gate keeps enforcing the last verified policy offline, even when it is stale. The freshness timestamp is local. Revoking a hub token blocks hub access. A cached policy can still give its previous grants. [Policy freshness](../trust-model.md#a-stale-policy-has-no-expiry-today) and [hub revocation](../trust-model.md#decisions-settled-by-the-hub-connection)
- The policy match budget undercounts character-class work in signed bundles. A check can take longer than its intended budget. A Codex hook timeout can let a call run. [Issue #62](https://github.com/Multiplexer-si/OpenPlexer/issues/62)
- All active members can access every project and Room in the single-team hub. Claims are advisory. The hub operator can read and change stored state and holds the signing keys. [Architecture and privacy](../architecture-and-privacy.md#what-each-setup-guarantees)
- Local decision logs stay on the developer's machine. The hub receives event metadata, some relative paths, and Room prose. Content filtering can miss code or secrets, and direct API posts bypass the daemon filter. The hub keeps Room history and the team audit chain indefinitely. [Data sent](../architecture-and-privacy.md#what-leaves-the-developers-machine) and [hub storage](../architecture-and-privacy.md#what-the-hub-stores-and-for-how-long)
- Without a trusted checkpoint, a valid prefix or a full rewrite with recomputed hashes can pass verification. A trusted checkpoint covers only its record count. It cannot establish whether the hub omitted events or kept a later checkpoint. Display fields and unknown fields lie outside the hash. The signing hub can assert its own issue time or sign a rewritten log. [Verifier limits](../audit.md#what-the-verifier-cannot-prove)
- The hub uses one server and one data directory. Its state snapshot grows with history. Key rotation commands and server-side content filtering remain future work. The hub reserves decision confirmation and override events for future services. [Hub operational limits](../hub.md#data-directory-and-operational-limits) and [HTTP API](../hub.md#http-api)
- Checkpoint delivery to daemons, daemon storage of received checkpoints, CSV export, and audit retention remain future work. [Audit guide](../audit.md#read-the-output)
- The Windows ZIP passed its SHA-256 check. The PowerShell install path and Windows runtime are unverified in this check. PowerShell tool calls are outside the Claude Code matcher. [Windows install](../install.md#windows) and [Claude Code hook coverage](../hooks-claude-code.md#what-the-hook-does-not-see)
